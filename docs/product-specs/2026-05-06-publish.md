# Publishing

Status: implemented contract
Last updated: 2026-07-18

## Goal

Writers can publish the active Markdown document to Ghost, WordPress
(self-hosted), WordPress.com, or Medium without leaving Novelist. Each action
targets one configured channel. Novelist retains that document/channel's form,
cover, and verified remote identity so later publishes can update the same post
when the provider supports it.

This spec covers publish channels only. The separate image-host feature can
rewrite local images before this flow begins.

## Non-Goals

- Cross-posting in one action. One publish action targets one channel.
  Cross-posting requires N separate user actions.
- YAML front-matter identity or metadata writeback. Any front matter in the
  source is stripped from the submitted body and otherwise ignored. Remote
  identity never lives in YAML.
- Browser-redirect auth flows. Manual paste of credentials only.
  Application Password browser flow (WP) and OAuth2 (WP.com) are
  deferred to a later release.
- Scheduled publishing UI. Status dropdown does not surface
  `scheduled` / `future`. Users who want scheduling can switch
  status on the platform's web UI after the post lands as a draft.
- Automatic identity inference, fallback creation, or overwrite. Recovery from
  conflict, deletion, corruption, or provider failure always requires an
  explicit user action.
- Medium update, legacy binding, or feature-cover support. The supported Medium
  Integration API can create posts and upload inline images, but cannot provide
  those three behaviors.

## Durable state

Publish identity is `(project document key, stable channel id)`. The canonical
project-relative document key is defined by the
[file-lifecycle contract](../design-docs/file-lifecycle.md); it supports CJK,
spaces, nested paths, and bounded long keys, and migrates during file or folder
rename. The channel key is `ChannelConfig.id`, never its editable display name.
Open-tab IDs are runtime UI state and are not durable Publish identity.

Each document has one `.novelist/publish/<document_key>.json` sidecar. Its
versioned `channels` map stores only:

- `form`: title, tags, excerpt, slug, status, and optional destination. A
  missing slug is a backward-compatible uninitialized value; an empty string is
  an explicit user clear and must not be regenerated on restore.
- `remote`: `{ post_id, url?, revision?, provider_revision?, capability? }`.
  `revision` reads legacy sidecars; current create, bind, and update flows store
  a typed `provider_revision` and capability when the provider exposes them.
  Medium create stores its create-only capability without a provider revision,
  and Medium binding is unavailable.
- `cover`: a validated content-hash reference, never raw bytes or a runtime
  object URL.

Credentials remain in global channel settings. Sidecars never contain tokens,
passwords, request data, transient errors, in-flight state, a transient
`success_url` field, raw image bytes, or browser object URLs. The durable
`remote.url` is intentionally persisted. Provider errors and transport text are
redacted and bounded before they cross the command boundary or enter logs and
evidence. Sidecar writes are atomic per file and
serialized across read-modify-write updates so channel siblings do not clobber
one another. The implementation contract is in
[`sidecar.rs`](../../core/src/services/publish/sidecar.rs).

Publish sidecars and cover assets use confined metadata directories rooted at
the canonical project. Reads, writes, temporary files, conflict copies, and
cleanup reject symlinked metadata directories/files and non-regular files.

Missing state starts with form defaults and no remote identity. Malformed
top-level JSON or an unsupported schema version is retained and reported; the
dialog does not auto-repair or overwrite it. A malformed form for one channel
is reported for that channel while valid sibling forms still restore.

## Provider behavior

| Platform | Create and body | Tracked update | Legacy binding | Cover |
|---|---|---|---|---|
| Ghost | Admin API key signs a fresh 5-minute JWT. Creates HTML with `POST /ghost/api/admin/posts/?source=html` and persists returned ID, URL, and `updated_at`. | Requires the tracked remote ID and expected Ghost `updated_at`. Authenticated GET verifies the same ID and revision, then PUT sends that revision. GET/PUT 404 becomes Not Found; a revision mismatch or PUT 409 becomes Conflict. All fail closed with no create fallback. | Supported. Authenticated ID or same-channel permalink lookup must return a canonical ID, URL, and `updated_at` before the remote field changes. | Supported through the Ghost image endpoint and `feature_image`. |
| WordPress self-hosted | Application Password with HTTP Basic auth. Creates HTML at `/wp-json/wp/v2/posts` and persists numeric ID, link, and typed `modified`/`modified_gmt`. | Authenticated `context=edit` GET verifies the same numeric ID and compares the stored non-empty revision fields, then POST updates `/posts/<id>`. A mismatch or 404 stops the flow. This is best-effort drift detection only: WordPress does not enforce the expected revision on the update request, so a change after GET can still be overwritten. The GET and POST are not one atomic provider transaction. | Supported. Authenticated ID, `?p=<id>`, or unique same-site slug lookup must return canonical ID, link, and revision. | Supported through the media endpoint and `featured_media`; an update without a supplied cover preserves the fetched media ID. |
| WordPress.com | Bearer auth. Creates HTML at the site-scoped `/wp/v2/sites/<site>/posts` route and persists numeric ID, link, and typed WordPress revision. | Same verified-ID and best-effort revision behavior as self-hosted WordPress, using the separate site-scoped route. It has the same race limitation and no cross-request atomicity guarantee. | Supported. Authenticated lookup verifies the selected site/domain, canonical ID/link, and revision. | Supported through the site-scoped media endpoint and `featured_media`; an update without a supplied cover preserves the fetched media ID. |
| Medium | Bearer Integration Token. Creates native Markdown for the authenticated user or selected publication and persists ID/URL with `unsupported_update: create_only_api`. At most three tags are submitted. | Unsupported. A tracked Medium identity blocks the default Publish action. Only a separately confirmed New Copy sends a create request. | Unsupported. `/v1/me` proves token validity, not post existence or ownership, so no legacy identity is saved. | No feature cover through this API. Inline body images may still use `/v1/images`; the Publish cover control is unavailable. |

The Ghost adapter follows the
[official Ghost update contract](https://docs.ghost.org/admin-api/posts/updating-a-post).
The WordPress adapters follow the
[official WordPress posts API](https://developer.wordpress.org/rest-api/reference/posts/)
and [official WordPress.com namespace reference](https://developer.wordpress.com/docs/api/namespaces-versions/).

## Configuration

Credentials are stored in global settings only. Per-project overrides are not
part of this contract.

```
GlobalSettings.publish:
  channels: [
    { id: <uuid>, name: "Personal Ghost", platform: "ghost", admin_url: "...", api_key: "..." },
    { id: <uuid>, name: "Company WP",     platform: "wordpress_self_hosted", site_url: "...", username: "...", app_password: "..." },
    { id: <uuid>, name: "WP.com Blog",    platform: "wordpress_com", site_id_or_domain: "myblog.wordpress.com", access_token: "..." },
    { id: <uuid>, name: "Medium",         platform: "medium", token: "..." },
  ]
```

There is no active-channel pointer. The user picks one stable channel for each
Publish action.

## User Behaviors

### Configuring channels (Settings → Publish)

- Add channel: pick platform, fill platform-specific form fields, save.
- Edit / Delete / Test buttons per channel.
- Test performs a read-only provider credential check. No post is created.

### Editor share button (new top-right toolbar)

A single dropdown button in the editor header contains:

- Copy HTML
- Export as… (delegates to existing export dialog)
- Upload Local Images to… (delegates to the configured image-host action)
- For each configured channel: `Publish to <name>`

Each `Publish to <name>` opens the publish dialog scoped to that
channel.

### Publish dialog (per-channel)

The header shows the channel display name and base URL.

Fields:

- **Title** is seeded from the first H1 when there is no persisted form, then
  remains editable and required.
- **Tags** are added with comma or Enter and can be removed.
- **Excerpt** is optional.
- **Slug** is seeded once from the first H1 when no owned value exists. The
  ASCII-only generator falls back to `post` for an empty or CJK-only H1. Once
  the field is edited, including being explicitly cleared, its exact value is
  retained independently of later title changes.
- **Cover image** is optional and unavailable for Medium.
- **Status** uses the provider-specific options below.

No Medium publication selector is currently rendered. The persisted form shape
retains an optional destination for compatibility, but the current UI does not
let the user choose or change it.

Per-platform status options:

| Platform | Status options | Default |
|---|---|---|
| Ghost | `draft`, `published` | `draft` |
| WP self-hosted | `draft`, `pending`, `private`, `publish` | `draft` |
| WP.com | `draft`, `pending`, `private`, `publish` | `draft` |
| Medium | `draft`, `unlisted`, `public` | `public` |

### Form persistence

Form changes are debounced to the document/channel sidecar. The dialog awaits
its current form before publish or bind, close, rename, and the registered
project-switch provider. Failed close or rename flushes keep the old owner
active and expose a retryable error. Project switching runs this provider before
loading-state, watcher, or destination-settings changes. A rejected provider
keeps the current project active and aborts the transition.
Svelte destruction starts a best-effort flush and logs rejection, but component
teardown cannot await it.

Close and reopen, app restart, provider failure, validation failure, successful
create, and successful update all retain the current form. A late disk restore
never overwrites input already typed in the open dialog. Form writes replace
only `form`; they preserve the same channel's cover and remote identity plus
all sibling channels. Legacy drafts that omit `slug` still receive the generated
default; drafts containing `slug: ""` restore the input as empty across document
and channel switches.

### Durable covers and paste

Ghost and both WordPress variants support one durable cover per
document/channel. Picker, drag/drop, the Paste button, and `Command+V` while the
cover target is focused all enter the same persistence queue. A direct
`ClipboardEvent` image is preferred. If WebKit supplies no image bytes, Rust
reads the system clipboard with `arboard`, converts it to PNG, and returns the
bytes without invoking the browser clipboard permission flow.

The cover paste handler is scoped to the cover target. Paste in title, tags,
excerpt, and slug falls through to native text behavior and never calls cover
IPC. Publish, close, rename, and the registered project-switch provider wait for
the pending cover queue before proceeding. Component destruction invalidates
the preview owner but cannot await pending asynchronous work.

The frontend rejects files above 25 MiB before reading them. Rust accepts only
PNG, JPEG, GIF, or WebP detected from magic bytes; a declared MIME mismatch or
unknown format fails without replacing the current cover. Accepted bytes are
stored atomically as `.novelist/publish-assets/<blake3>.<ext>`, naturally
deduplicating identical content. Restore validates reference shape, byte count,
BLAKE3 hash, detected MIME, and extension before returning bytes.

Replacement writes the new asset and cover reference before reference-safe
orphan cleanup. Clear removes only the target channel's reference, then cleanup
deletes canonical assets that no active or conflict sidecar references. Cleanup
scans every Publish JSON file first and fails closed on malformed data, so it
never guesses that an unreadable sidecar has no references. A cleanup failure
does not undo the already committed cover mutation and is safe to retry.

Preview object URLs have one owner. Replacement creates the next URL before
revoking the previous one; clear and component destruction revoke the current
URL exactly once. Object URLs and raw bytes are never serialized.

### Publish pipeline

On Publish click, the orchestrator:

1. Flushes the retained form and waits for cover persistence.
2. Chooses create or update strictly from the verified durable remote state and
   explicit recovery intent. Missing identity creates; an updatable identity
   updates the same remote ID; unsupported or corrupt identity blocks.
3. Before a tracked WordPress or WordPress.com update, performs an authenticated
   `context=edit` GET through the provider-specific preflight command and
   compares the durable expected revision. Conflict, not-found, or auth failure
   stops here, before any body-image or cover upload.
4. Strips any YAML front matter from the submitted body.
5. Enumerates `![alt](path)` references whose target is not an HTTP(S) or data
   URL.
6. For each local reference, reads through the scoped `read_image_bytes`
   capability and then calls `upload_post_image_<platform>(bytes, ...)` to
   upload to the publish target's own media endpoint, returning the
   platform-hosted URL.
7. For a non-Medium create or confirmed New Copy, uploads an available durable
   cover. For a tracked update, uploads the cover only when the user selected or
   pasted a replacement during the current panel attempt. Restoring the durable
   cover for preview does not mark it changed. An unchanged WordPress cover is
   omitted from the frontend payload, and the adapter reuses the fetched
   `featured_media` ID.
8. Rewrites the body, replacing each local reference with the new URL.
9. For Ghost / WP / WP.com, converts the rewritten Markdown to HTML
   via the configured external Pandoc binary.
10. For Medium, passes the rewritten Markdown unchanged with
   `contentFormat: "markdown"`.
11. Submits the provider create or update request, then atomically persists the
     returned remote identity and refreshed revision.

The WordPress adapters retain their own revision GET so direct adapter callers
remain fail-closed. A tracked WordPress attempt with uploads therefore has the
observable provider order: preflight GET, optional media POSTs, adapter GET,
post-update POST. An unchanged restored cover removes the cover media POST from
that sequence. Creates and confirmed New Copy requests do not run update
preflight.

If any image upload, conversion, provider, or identity-persistence step fails,
the dialog stays open and retains the form and cover. Body rewriting is
in-memory only; the CodeMirror buffer and Markdown file are never changed.

If the user wants images hosted on a third-party CDN instead of the
publish platform, they explicitly run the `Upload Local Images to…`
share-menu action first (which uses the configured image host); the
publish step then sees no local references and skips upload.

Local image reads are capability-relative. Rust owns retained directory
capabilities per window: starting a project watcher registers the project root,
and opening a standalone document registers its document directory. The webview
supplies only the document base and Markdown reference. In project mode the
document directory must be a normal descendant of the registered project; in
single-file mode it must match a registered document directory.
The Markdown reference itself must be relative and contain no parent component.
Absolute paths, `..`, symlinked files, symlinked parent directories,
non-regular files, and paths changed during the descriptor walk fail before
image bytes are returned or any provider upload begins. Parent directories are
opened one component at a time through retained `cap_std::fs::Dir` handles; the
final file is opened from the retained root with no-follow semantics. Owner
capabilities are revoked on file unregister, watcher stop, and window destroy.
Rejected reads return bounded reason codes without echoing the root, candidate
path, or file bytes. Ordinary nested
references and CJK filenames remain supported. The current lightweight Markdown
extractor does not accept raw spaces in inline image destinations. Durable
covers continue to support CJK/space filenames through the separate confined
`.novelist/publish-assets` path described above.

### Remote lifecycle and recovery

The dialog exposes `Checking`, `Unavailable`, `New`, `Updating`, `Updated`,
`Conflict`, `Not Found`, `Unsupported`, and `Corrupt` states. On success, it
keeps the form and cover, shows the returned URL, and offers Open in Browser.
Reopening a tracked channel returns to Updating and the next default Publish
targets the same ID.

- **Open Remote** validates the durable or newly returned provider URL again at
  the system-shell boundary, including for a tracked Medium post. It accepts an
  absolute credential-free HTTPS URL with a non-empty hostname. HTTP is allowed
  only for self-hosted Ghost and self-hosted WordPress channels; localhost,
  private IPv4 addresses, and non-public hostnames remain supported for those
  workflows. Raw controls, whitespace, unsafe ASCII, backslashes, malformed
  authority, hostname labels, or percent encoding, relative and local paths,
  and non-HTTP(S) schemes are rejected with bounded generic feedback before any
  shell call. Accepted CJK paths and valid percent encoding are passed to the
  opener exactly as supplied.
- **Attach Existing / Rebind** is available only for Ghost and both WordPress
  variants. Rust resolves credentials from the selected saved channel,
  authenticates the lookup, validates site ownership and canonical identity,
  then changes only the target channel's `remote` field. Form, cover, and
  siblings remain intact. Failure leaves the old sidecar bytes unchanged.
- **Conflict** sends no automatic retry. The user may confirm Overwrite
  Existing, which resubmits an update with the provider-reported current
  revision when available, or confirm New Copy.
- **Not Found** sends no create request. The available recovery is an explicit,
  separately confirmed New Copy or a successful Rebind.
- **Unsupported** blocks default publishing. For Medium, only confirmed New
  Copy creates another post; legacy binding and overwrite are unavailable.
- **Checking / Unavailable** represents remote identity that has not been
  confirmed or whose read failed. Unknown identity is distinct from confirmed
  unbound `null`: Publish, New Copy, binding, cover mutation, tag-provider work,
  and local form persistence remain blocked. Retry must confirm the same
  document/channel state before provider work resumes. A prior same-owner
  identity may remain visible in disabled affordances but is never used to plan
  a request. Late reads from a retired document/channel owner are ignored.
- **Corrupt** is shown when confirmed durable identity lacks the capability or
  revision required for a safe update. Malformed sidecar JSON also makes the
  remote-state read unavailable. Rebind is not a general repair path for
  unreadable top-level sidecar JSON because its atomic mutation also requires a
  readable sidecar.

There is no automatic create or overwrite after conflict, not-found, auth,
network, media, malformed-sidecar, or persistence failure. New Copy keeps the old identity
through provider and local failures. It rotates `remote` only after the new
create result has been successfully persisted, and leaves form, cover, and
sibling channels unchanged.

If the provider succeeds but local identity persistence fails, the panel keeps
that exact provider result in a bounded in-memory recovery state. Publish and
exit remain blocked; Retry repeats only `persist_publish_result`, never the
provider create/update request. Once persistence succeeds, the panel becomes
Updated and normal close/navigation resumes.

## Acceptance Criteria

- A user with valid Ghost, WordPress, WordPress.com, or legacy Medium
  credentials can configure a channel and create a post.
- First create persists canonical remote identity. A later Ghost or WordPress
  publish updates the same verified ID and refreshes its typed revision.
- Conflict, not-found, malformed sidecar state, unsupported update, and
  provider failure never issue an implicit create or overwrite. A transient
  remote-state read error remains Unavailable and must be retried before
  Publish; it is never projected to an unbound identity.
- Open Remote issues exactly one shell call for an accepted provider URL and no
  shell call for a rejected persisted or provider-returned value. Rejection
  feedback never includes URL credentials or the raw rejected value.
- Authenticated legacy binding is available for Ghost and both WordPress
  variants, preserves form/cover/siblings, and is unavailable for Medium.
- Local image references in the doc are uploaded to the platform's
  media endpoint and replaced with platform-hosted URLs in the
  submitted body.
- Parent traversal, absolute paths, symlink components, and directory-swap
  races in local image references fail before image bytes or provider requests.
- Failed image upload aborts before post submission.
- Ghost JWT auth is generated fresh per request with a 5-minute TTL.
- Ghost requires the expected `updated_at`; stale revision and provider 409
  become Conflict, and 404 becomes Not Found.
- WordPress revision comparison is documented as best-effort and never as an
  atomic provider-side guard.
- Publish forms and supported covers restore across close/reopen and remain
  after success or failure. Explicitly cleared slugs stay empty; only an omitted
  legacy/uninitialized slug receives the generated default.
- Focused cover `Command+V` prefers event image bytes and uses Rust clipboard
  fallback; text paste elsewhere remains native.
- Cancelling an idle publish dialog does not modify the document. Body changes
  made for submission remain in memory and are discarded when the flow ends.
- The CodeMirror document buffer is never modified by publish
  operations. Local image references stay local in the user's source.

  [`publish.rs`](../../core/src/commands/publish.rs) cover atomic preservation,
  CJK keys, corruption, content addressing, replacement/clear, orphan cleanup,
  remote persistence, and binding isolation.
- **Rust confined image-read tests** in
  [`image_host.rs`](../../core/src/commands/image_host.rs) cover parent
  traversal, absolute paths, symlinked roots/files/parents, deterministic
  pre/post-verification directory replacement, owner isolation/revocation,
  replaced roots, sanitized errors, and nested CJK/space paths.
- **Pandoc helper tests** cover paragraph, heading, and CJK conversion plus
  missing-binary and non-UTF-8 output errors. They skip real conversion when
  Pandoc is unavailable. The separate ignored styled-copy real-Pandoc matrix
  covers richer tables and code highlighting; this Publish spec does not claim
  a focused image/code conversion matrix.
- **Frontend unit tests** in
  [`tests/unit/services/`](../../tests/unit/services/) cover form persistence,
  lifecycle planning, typed error classification, cover object URL ownership,
  platform routing, and image rewriting. The focused
  [`publish-url.test.ts`](../../tests/unit/utils/publish-url.test.ts) matrix
  covers the Open Remote parser and lexical boundary.

  [`tests/e2e/specs/publish-update.spec.ts`](../../tests/e2e/specs/publish-update.spec.ts),
